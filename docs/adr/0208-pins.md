# ADR 0208: Pins: a canvas in a window above every view

- Status: **accepted** (2026-11-22, revised 2026-11-23); supersedes ADR 0207 (reference windows)
- Related: ADR 0123 (panel dock), 0205 (every action a command), 0009/0010 (tiles, density)

## Context

The reference windows (ADR 0207) grew a world of their own: moodboards stored apart from canvases, their own handles, pan and zoom,
flip, order, undo, copy and paste, grid, gallery, viewer and window. Each copied something the canvas or the Library already had, and each
copy behaved a little differently (F, the handles). The owner asked for them to be rebuilt on the app's own parts, named **Pins**, in a
module of their own (`src/pins/`), and kept a simple reference view around the app: for looking and arranging, the work itself done in the
main view.

## Decision

- **A Pins window shows a canvas of the workspace or pictures of the library**, chosen in it: its boards and canvases (the navigator's
  icons), **All pictures**, folders shown lately, or any folder by its name (the shared folder chooser). There are no moodboards: a pinned
  canvas is a canvas.
- **The same engine**: the canvas engine is a module (`src/canvas/canvas-view.ts`, `createCanvasView`) made once for each view: the main
  view and each pinned one. Its surface is wired by the main view's own function (`wireCanvasView`: tools, navigation, menu, drops, cursor),
  with the hooks the main view's are made from (`toolHooksFor`); the commands' actions are made per view (`canvasActionsFor`, `barActionsFor`).
- **The view in use** (`src/canvas/focus.ts`): the last pressed, a Pins window or the main view. Every command, key, menu row, paste and the
  Actions bar go to it, over any view (the Library, PhotoCraft: a press in a window takes the keys back from PhotoCraft's frame). The main
  view's own keys stand down while a window is in use; a press outside every window gives them back.
- **A simple view**: the Actions bar in a window has its Arrange only (no Keep it tidy), its right-click menu and a finger held still give a
  short menu (`PINS_MENU_ROWS`). Writing or editing text, the list of what is under the pointer and search stay the main view's.
- **One canvas, one document**: the canvas the main view shows is shown in Pins from the main view's very document (the edits and the undo
  are the same). Another canvas is read into a document of its own, saved by the same `CanvasPersistence`; when the main view opens it, or
  leaves the one Pins shares, Pins changes document, so a canvas is never held twice. Pictures that finish loading redraw every view.
- **Pictures of the library** are a second Library (`mountAssetsView(…, { embedded })`): its own grid of the folder, then its viewer on a
  double-click, without its bar, sidebar, details, Full screen or Place. Its commands are the Library's, given by each Library and run for
  the one in use (`provideLibraryCommands`); its menus keep what is for looking (favourite, copies, open elsewhere).
- **A panel of the dock** (ADR 0123) with `everywhere` (a free layer above every view) and `height` (a grip at the bottom corner sizes both).
  The windows open are kept on the device (`pins.windows`), their places by the dock.
- **The window's options**: its opacity (the shared settings rows), clicks through it, and, in the desktop app, a live picture of it floated
  above every app (`pins.float`: a sandboxed page with no script; the app sends it a new picture when the canvas is drawn again).
- **Bringing pictures over**: a card dragged onto a pinned canvas, a picture dragged off the main canvas, files dropped from another app, a
  picture pasted from another app (into the library, then the middle of the window): all placed by the same code as on the canvas
  (`placeIn`, `takeDrops`).
- Shift+R and the button by Settings pin the canvas open (`pins.open`); `pins.show`, `pins.window`, `pins.float` and `pins.close` are the
  window's commands.
- **The moodboards** of the reference windows became canvases, once, of a board named Pins (`pins/migrate.ts`), every picture where it
  was, flipped, turned and see-through as it was; ADR 0207's window, its commands and its storage are gone.

## Consequences

- Everything a canvas or the Library does works in Pins and stays so as they grow: nothing is copied.
- A pinned canvas does not write or edit text, list what is under the pointer or search: by design, those are the main view's.
- Float over other apps is a picture of the window, updated as it changes: the floated window itself takes no input.
