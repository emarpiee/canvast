# ADR 0208: Pins: a canvas in a window above every view

- Status: **accepted** (2026-11-22); supersedes ADR 0207 (reference windows) once Pins has its gallery
- Related: ADR 0123 (panel dock), 0205 (every action a command), 0009/0010 (tiles, density)

## Context

The reference windows (ADR 0207) grew a world of their own: moodboards stored apart from canvases, their own handles, pan and zoom,
flip, order, undo, copy and paste, grid, gallery, viewer and window. Each copied something the canvas or the Library already had, and each
copy behaved a little differently (F, the handles). The owner asked for them to be rebuilt on the app's own parts, named **Pins**, in a
module of their own.

## Decision

- **A Pins window shows a canvas of the workspace**, chosen in it (its boards and canvases, the navigator's icons). There are no moodboards:
  a pinned canvas is a canvas.
- **The same engine**: the canvas engine is a module (`src/canvas/canvas-view.ts`, `createCanvasView`) made once for each view: the main
  view and each pinned one. The tools are `attachTools` on the window's own drawing surface, with the hooks the main view's are made from
  (`toolHooksFor`); the commands' actions are made per view (`canvasActionsFor`) and `src/canvas/focus.ts` sends every command, key and menu
  row to the view in use (the last pressed). The tools take keys only while their view is in use (`ToolHooks.active`).
- **One canvas, one document**: the canvas the main view shows is shown in Pins from the main view's very document (the edits and the undo
  are the same). Another canvas is read into a document of its own, saved by the same `CanvasPersistence`; when the main view opens it, or
  leaves the one Pins shares, Pins changes document, so a canvas is never held twice.
- **A panel of the dock** (ADR 0123) with two new options: `everywhere` (a free layer above every view, the Library too) and `height` (a
  grip at the bottom corner sizes both). `remove(id)` closes one for good. The windows open are kept on the device (`pins.windows`), their
  places by the dock.
- Shift+R and the button by Settings pin the canvas open (`pins.open`); `pins.show` and `pins.close` are the window's commands.

## Consequences

- Everything a canvas does works in Pins and stays so as the canvas grows: nothing is copied.
- For now a pinned view edits text, lists what is under the pointer and searches through the main view only (its hooks for those do
  nothing); the Actions and Properties bars follow the main view.
- The gallery of the Library's folders comes to Pins from the Library's own cards and viewer (next), then ADR 0207's window and its
  moodboards go (converted once into canvases).
